# 현농푸드랩 모바일 와이어프레임 v1

2026년 9월 9일 · 글 상세와 홈의 화면 배치안. 사진·문구·게시일은 공개 원고가 아닌 배치 검토용이며, 브랜드 색상·실제 촬영물은 다음 시각 디자인 단계에서 반영한다.

상호작용 원본은 같은 폴더의 `mobile-wireframes.html`이다. 대화에서 ‘글 상세 / 홈’을 전환해 읽을 수 있으며, 프로젝트에서도 이 원본을 이어서 수정한다.

## 반영한 결정

- 공통 외부 채널은 [스마트스토어 홈](https://smartstore.naver.com/hnfoodlab)과 [인스타그램 @hnfoodlab](https://www.instagram.com/hnfoodlab/)이다. 외부 링크는 새 탭으로 열리고 화살표로 구분한다.
- 스마트스토어는 모바일 메뉴와 하단에, 인스타그램은 하단에 둔다. 인스타그램은 이후 소개 페이지의 공식 채널에도 연결한다.
- 네이버 블로그를 웹사이트의 외부 채널에 넣지 않는다. 네이버 원고 제작·발행과 웹사이트·스토어로 유입시키는 운영은 기존 기준을 따른다.
- 로고는 홈으로 이동한다. 모바일 메뉴는 블로그 → 바른쌀 누룽지 → 현농푸드랩 소개 → 스마트스토어 순서다.

## 공통 화면 기준

| 항목 | 배치 기준 |
|---|---|
| 화면 폭 | 최대 390px, 더 좁은 화면에서는 가용 폭에 맞춤 |
| 본문 좌우 여백 | 기본 22px. 배치 옵션에서 16~24px 비교 |
| 글 본문 | 16px, 첫 답변 17px. 충분한 행간과 문단 간격 |
| 메뉴 | 로고 옆 ‘메뉴’ 버튼. 열면 헤더 아래에 펼쳐지는 방식 |
| 터치 영역 | 주요 메뉴·링크·버튼 최소 44px 높이 |
| 사진 | 실제 사진의 위치·비율만 표시. 가상의 제품 사진·시험 결과 없음 |
| 하단 | 브랜드 → 스마트스토어·인스타그램 → 운영 주체·문의 안내 |

와이어프레임은 중립적인 색으로 배치와 위계를 살핀다. 상단 고정 구매 배너 없이 본문 안의 다음 행동을 중심으로 연결한다.

## 글 상세 배치

1. 공통 헤더와 현재 경로.
2. 주 분류 → 질문형 제목 → 작성자·게시일.
3. 질문에 대한 짧은 답. 큰 이미지를 앞에 두지 않는다.
4. 펼치고 접을 수 있는 목차.
5. 본문 소제목·설명 → 마른 상태/조리 후 실제 사진 두 장 → 조건을 표시하는 캡션.
6. 추가 설명 → 자료와 확인 기준.
7. 바른쌀 안내로 이어지는 주된 버튼 하나.
8. 관련 글 두 편과 공통 하단.

소재 예시는 ‘누룽지 40g은 어느 정도일까요?’다. 사진 자리는 두 이미지를 나란히 비교하는 용도이며, 촬영 때 동일 그릇·각도와 물 양·조리 시간을 함께 기록한다. 실제 결과와 검수된 원고를 확보한 뒤 공개 내용으로 교체한다.

## 홈 배치

1. 공통 헤더.
2. 브랜드가 다루는 이야기 → 짧은 소개 → 가로형 상품·조리 사진 → 블로그 읽기.
3. 처음 읽기 좋은 글: 주 분류·제목·짧은 설명·게시일로 구성한 목록.
4. 바른쌀 상품 안내: 실물 포장 사진과 요약 → 상품 안내 버튼.
5. 충분한 글이 있을 때 최근 글.
6. 현농푸드랩 소개 요약과 공통 하단.

초기 상태는 글 3편이다. 대표 글과 최근 글을 한 영역에 모아 같은 글을 반복하지 않는다. 배치 옵션에서 ‘글 없음 / 초기 3편 / 6편으로 증가’를 비교할 수 있다.

- 글 없음: 글 영역을 생략하고 첫 행동을 바른쌀 안내로 연결한다.
- 초기 3편: 처음 읽기 좋은 글만 표시한다.
- 6편: 처음 읽기 좋은 글 3편과 중복되지 않는 최근 글 3편을 표시한다.

이는 와이어프레임의 예시 상태다. 실제 웹사이트에는 공개 대상으로 확정된 원고만 포함한다.

## 동작과 연결 범위

홈의 첫 글을 누르면 글 상세로, 로고를 누르면 홈으로 이동한다. 메뉴 열기·닫기와 Escape 키, 목차 이동, 자료 펼치기도 동작한다.

스마트스토어와 인스타그램은 사용자 제공 주소로 실제 연결했다. 제공된 스마트스토어 주소는 스토어 홈이므로 특정 상품·옵션이 바로 열리는 것으로 표현하지 않는다.

블로그 목록·상품·소개·다른 글은 이번 두 화면에 포함되지 않는다. 해당 링크를 누르면 검토용 연결 대상 안내를 보여준다. 이 안내창과 화면 전환 버튼·배치 옵션은 검토 도구이며, 실제 웹사이트의 독자 화면에는 넣지 않는다.

## 확인 결과와 다음 단계

HTML 참조·고유 ID·외부 주소와 스크립트 문법을 확인했다. 모의 DOM 실행으로 화면 전환, 메뉴와 Escape, 목차 대상, 연결 안내창, 홈의 0/3/6편 상태를 확인했다.

실제 브라우저 렌더링 검증은 로컬 파일 접근 제한으로 수행하지 못했다. 좁은 화면과 실제 사진을 반영한 상태의 최종 시각 검증은 다음 구현 단계에서 이어간다.
